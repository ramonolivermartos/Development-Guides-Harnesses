The journey of a request in Spring Boot with security

From the moment the client makes a call until the database responds, a request crosses several layers. Each one has a single responsibility. Choose a scenario and move through it step by step to see who acts, which code is involved, and where the journey can stop.

Walk through a request

    Why DTOs and mappers sit in between

    The entity reflects your table. The DTO is the contract with the client. Toggle between the options to see what happens in GET /api/users/me if you return the entity directly.

    Authentication and authorization at three levels

    Authentication answers “who are you?” and, if it fails, returns 401. Authorization answers “what are you allowed to do?” and, if it fails, returns 403. Authorization is best checked across several layers at once.

    Level 1: the route (SecurityFilterChain)
    General rules by URL and HTTP method. This is the first barrier and the least expensive one.
    .authorizeHttpRequests(a -> a
  .requestMatchers("/api/auth/**").permitAll()
  .requestMatchers(HttpMethod.DELETE, "/api/orders/**").hasRole("ADMIN")
  .anyRequest().authenticated())
    Level 2: the method (@PreAuthorize)
    Protects the logic even if someone calls it from another entry point. It requires @EnableMethodSecurity in your configuration.
    @PreAuthorize("hasRole('ADMIN')")
public void deleteOrder(Long id) { ... }
    Level 3: the data (is this order yours?)
    No route rule knows who owns order 7. That check belongs in the service, using the user from the SecurityContext. It is what prevents Ana from reading Luis’s orders.
    if (!order.getOwner().equals(currentUsername())) {
    throw new AccessDeniedException("This is not your order");
}

    How the work is divided

    com.example.shop
├── config      SecurityConfig
├── security    JwtAuthFilter, JwtService, UserDetailsServiceImpl
├── order
│   ├── OrderController      HTTP only
│   ├── OrderService         rules, transactions, ownership
│   ├── OrderRepository      data access only
│   ├── OrderMapper          entity and DTO
│   ├── Order                JPA entity
│   └── dto                  CreateOrderRequest, OrderResponse
└── error       GlobalExceptionHandler (@RestControllerAdvice)
    Controller
    Translates HTTP to DTOs and back, validates with @Valid, and delegates. No business logic and no direct access to repositories.
    Service
    Business rules, @Transactional, and ownership checks belong here. It returns DTOs so that entities do not leave this layer.
    Repository
    Queries only. If you start adding business-related if statements, that logic belongs in the service.
    Passwords and secrets
    Hash passwords with BCryptPasswordEncoder; never store them in plain text. The JWT secret goes in an environment variable, not in the repository, and tokens should expire soon.
    Errors
    A @RestControllerAdvice converts exceptions into consistent JSON responses. Do not expose stack traces.
